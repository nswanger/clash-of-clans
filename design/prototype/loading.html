Loading

A skeleton is a muted placeholder in the exact shape of the content that is arriving — a bar where each name will be, a shorter one where its stat will be. It replaces both the spinner and the word “Loading”, and because it occupies the same space as the real row, nothing moves when the data lands.

Today, and the pattern

Today
Loading your war room…

One of six such strings across five files, with no CSS at all. It also announces itself, which the system’s own rule forbids: if the user cannot act on it, it is not a notice.

Clan Muster

Same row, same height, same padding — the skeleton is .row with blocks instead of content, so it cannot drift from the thing it stands in for.

The threshold

Nothing renders for the first 250ms. A fast load therefore shows no skeleton at all — try it — because a placeholder that appears and vanishes inside a tenth of a second is a flash, and reads as breakage rather than progress. Only a wait long enough to notice gets acknowledged, which is the honest rendering of “this was a wait”.

Re-fetching, with content already on screen

The list does not become a skeleton. Replacing populated rows destroys your reading position to tell you something the button already said — so the control that triggered the fetch owns the pending state, and the content stays put. A background refresh gets nothing at all, because the freshness line already reports it.

What carries it for screen readers

No visible copy anywhere, so the announcement is aria-busy on the region plus one visually hidden live region — present in this page, and the reason deleting the six strings costs nothing in accessibility terms.
